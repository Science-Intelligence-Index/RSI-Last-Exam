# Public disclosure boundary

用户全局守则（2026-10-18）：在任何时候，不要在公开仓库直接介绍或包含 SII Bench 精确的核心数据设计流程；可以使用概念性、描述性语言。不得用零散内容的组合间接还原流程。该规则适用于本仓库所有开发、文档维护与发布工作。

SII Bench's precise core data-design process must never be described or included in a public repository. Public material may explain concepts, goals, scientific questions, capabilities and domains in descriptive language.

This rule applies to source code, comments, documentation, diagrams, examples, fixtures, downloads, generated assets, commit messages, pull requests and issues. Do not publish internal documents or combinations of details that reconstruct the protected process. A closed-source workbench specification is not automatically public material.

Clearly distinguish attributed public teaching examples and third-party research from SII Bench's core design. Retain necessary scientific facts and source notices. An example is not permission to disclose the protected process.

Before publishing, inspect the staged changes and reachable generated assets. Keep precise designs in an authorized non-public location; do not place sensitive backups in this repository. When disclosure scope is uncertain, use conceptual descriptions and continue work within that boundary. Do not rewrite remote history or change repository visibility without authorization.
